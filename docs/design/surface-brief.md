# Pilot reference

Mode: Operate. Target: `design/index.html`. This reference expands the supplied map and readings screens within their established crimson field-tool identity; it does not implement the Android application or revise the approved pilot behavior.

User selected a clickable prototype plus guide, direct construction, and design checks during work on 2026-11-17.

## Direction contract

THESIS: A student can record a sample, understand whether it has a pin, and find it again. Remove the original reference's sync, export, ping, carrier metadata, and live-monitoring language.

OWN-WORLD: Collegiate crimson primary action, solid white task surfaces, quiet warm-neutral canvas, dark readable type, and labeled green/amber/red ratings. Retain the supplied two-destination architecture. ENERGY 1 / RHYTHM 1 / MOTION 1.

STORY: The map shows individual samples. Record one reading. Inspect its outcome and details. Continue through the readings list when tiles fail. Demonstration data and schematic geometry are explicitly identified.

FIRST VIEWPORT: A local design workbench presents a 412-wide Android-style viewport, map with five tappable sample pins, three shared filters, a compact explanation, bottom recording panel, and Map/Readings navigation. Desktop annotations sit beside the viewport; compact browsers stack them without shrinking the app.

FORM: Scoped refinement of the supplied map/list composition. No identity tournament or concept seed: existing visual authority and the spec fix the task and topology. The signature interaction is one recording operation progressing through location, saving, and confirmed result with the same shared details surface.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Deliverables and boundaries

Standalone local prototype; light/dark tokens; details; first-use permission explanation; capture states; no-pin reasons; map, signal, storage and read errors; empty states; screenshot plates; implementation guide and verification evidence. Simulated readings are held in memory and reset on reload. No sensor, storage, OS permission, basemap or phone integration is claimed. Native screens retain the two destinations required by the spec even though generic navigation guidance often assumes three.

## Verification

Exercise shared filters, pin/list details, show-on-map, permission choices, capture/save retry, map recovery, all scenario controls, Escape/back, dark mode, narrow widths, and enlarged text in a browser. Native TalkBack, Android Back, system permissions, real storage and campus placement remain later implementation checks.
